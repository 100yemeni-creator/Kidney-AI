# Kidney AI | نظام ذكي لتصنيف صور الكلى

مشروع تطبيقي في مجال **التعلم العميق والرؤية الحاسوبية**، يهدف إلى تصنيف صور الكلى إلى أربع فئات باستخدام شبكة **VGG16**. يتضمن المشروع واجهة ويب لرفع الصور وعرض الفئة المتوقعة ودرجات التصنيف.

> **تنبيه طبي:** هذا المشروع تجريبي وتعليمي، وليس أداة تشخيص طبي معتمدة. لا ينبغي الاعتماد على نتائجه لاتخاذ قرارات طبية.

---

## 1. نظرة عامة

يستخدم المشروع نموذج تعلم عميق لتحليل الصورة المدخلة وإسنادها إلى إحدى الفئات التالية:

| الفئة | الوصف |
|---|---|
| `Cyst` | كيس كلوي |
| `Normal` | كلية طبيعية وفق تصنيفات البيانات |
| `Stone` | حصوة كلوية |
| `Tumor` | ورم كلوي |

تعرض الواجهة الفئة المتوقعة ودرجات الفئات الأربع. هذه الدرجات ليست ضمانًا لصحة النتيجة، ودرجة النموذج المستخدمة حاليًا غير معايرة.

## 2. المتطلبات

لتشغيل واجهة المشروع تحتاج إلى:

- Python 3.8.20.
- الاعتماديات المحددة في `requirements.txt`.
- ملفات النموذج المطلوبة داخل مجلد `models`.
- بيئة Conda مخصصة للمشروع.

### إنشاء بيئة العمل

نفّذ الأوامر التالية من الطرفية:

```bash
conda create -n kidney_mlops python=3.8.20 -y
conda activate kidney_mlops
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

## 3. ملفات النماذج المطلوبة

قبل تشغيل الواجهة، تأكد من وجود الملفات التالية داخل مجلد `models`:

- `best_finetuned_model.h5` — النموذج المحسّن المستخدم في الواجهة.
- `fine_tuned_confidence_uncalibrated.json` — إعدادات درجات النموذج.

يتوفر أيضًا النموذج الأساسي:

- `best_candidate_model.h5`

**ملاحظة:** أوزان النماذج بامتداد `.h5` مستثناة من Git العادي. استنساخ المستودع وحده لا يضمن توفرها على جهاز جديد؛ يجب توفير الملفات المطلوبة ووضعها في مجلد `models`.

## 4. تشغيل واجهة الويب

بعد تفعيل بيئة `kidney_mlops` وتثبيت الاعتماديات، انتقل إلى المجلد الرئيسي للمشروع وشغّل:

```bash
python app.py
```

افتح المتصفح وانتقل إلى:

**http://127.0.0.1:5000**

لا يؤدي تشغيل `app.py` إلى بدء تدريب جديد؛ بل يشغّل واجهة التطبيق باستخدام ملفات النموذج المحلية.

### الصور المدعومة

تقبل الواجهة الصيغ التالية:

- JPG
- JPEG
- PNG
- BMP
- TIFF
- WEBP

الحد الأقصى لحجم الصورة هو **10 ميغابايت**.

بعد رفع الصورة، تعرض الواجهة الفئة المتوقعة ودرجات الفئات الأربع.

## 5. البيانات المستخدمة

تتكون مجموعة الصور المحلية من **11,929 صورة** موزعة كما يلي:

| المجموعة | عدد الصور |
|---|---:|
| التدريب | 8,348 |
| التحقق | 1,788 |
| الاختبار | 1,793 |
| **الإجمالي** | **11,929** |

### ملاحظات حول جودة التقييم

لم يكشف الفحص السابق عن تطابق تام في قيم SHA-256 بين مجموعات البيانات، لكن فحص التشابه البصري أظهر صورًا شديدة التشابه عبر المجموعات.

لا تتوفر معرّفات المرضى أو الدراسات؛ لذلك لا يمكن إثبات استقلال المجموعات على مستوى المرضى اعتمادًا على الفحوص المذكورة وحدها.

تبقى الصور وملف `manifest` والأرشيفات محلية، وهي مستثناة من Git.

## 6. أوامر خط العمل والتدريب

لعرض الأوامر المتاحة دون بدء التدريب، استخدم:

```bash
python main.py --help
```

الأوامر التالية تنفذ عمليات فعلية وليست مجرد أوامر لعرض المساعدة:

```bash
python main.py train-baseline
python main.py fine-tune
python main.py evaluate-validation
```

لا تستخدم هذه الأوامر لمجرد تشغيل الواجهة.

كذلك، فإن الأمر:

```bash
dvc repro
```

يشغّل مراحل خط العمل، بما فيها مراحل التدريب.

## 7. نتائج التقييم وحدودها

في اختبار سابق، صُنفت الصور الـ1,793 الموجودة في مجموعة الاختبار الحالية كلها بصورة صحيحة وفق التسميات المسجلة في البيانات.

لكن يجب تفسير هذه النتيجة بحذر للأسباب التالية:

- ظهرت صور شديدة التشابه بين مجموعات البيانات.
- لم تتوفر معرّفات المرضى أو الدراسات للتحقق من الفصل على مستوى المرضى.
- لا تثبت النتيجة الأداء المتوقع على صور مستقلة أو مرضى جدد.
- استُخدمت مجموعة الاختبار بالفعل، لذا لا ينبغي إعادة استخدامها لضبط النموذج.
- درجات النموذج المعروضة حاليًا غير معايرة، ولا تمثل ضمانًا لصحة التصنيف.

بناءً على ذلك، لا تكفي نتيجة الاختبار السابقة وحدها لإثبات قدرة النظام على التشخيص السريري.

## 8. حماية البيانات وسلامة المستودع

للحفاظ على المشروع بصورة منظمة وآمنة:

- لا ترفع صور البيانات أو ملف `manifest` أو الأرشيفات إلى GitHub.
- أوزان النماذج مستثناة من سجل Git العادي.
- لا ترفع كلمات المرور أو مفاتيح الوصول أو أي بيانات سرية.
- وفّر ملفات النماذج المطلوبة بصورة منفصلة عند إعداد نسخة جديدة من المشروع.
- حافظ على الفصل بين تشغيل الواجهة وتشغيل عمليات التدريب والتقييم.

## 9. هيكل المشروع

يتضمن المستودع مكونات رئيسية مثل:

- `app.py` — تشغيل واجهة الويب.
- `main.py` — نقطة الدخول إلى أوامر خط العمل.
- `config/` — ملفات الإعدادات.
- `models/` — ملفات النماذج وإعدادات الدرجات.
- `src/` — مكونات المعالجة والتدريب والاستدلال والتقييم.
- `templates/` — قوالب واجهة الويب.
- `static/` — ملفات التنسيق والموارد الثابتة.
- `requirements.txt` — اعتماديات Python.



**Kidney AI** مشروع تعليمي لاستكشاف تطبيقات التعلم العميق في تحليل صور الكلى، مع توثيق متطلبات التشغيل وحدود التقييم واعتبارات حماية البيانات.
